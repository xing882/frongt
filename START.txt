建筑能源演示系统 — 启动说明（赛题 A08 对齐）
============================================

【文档】
- 技术说明（架构/数据流/部署）：building_energy_system\docs\TECHNICAL.md
- 前端对接（全量 API、fetch 示例、赛题对照表）：building_energy_system\docs\API_FRONTEND.md
- 契约：浏览器打开后端 /docs 或 GET /openapi.json

============================================

【数据集（相对路径，与仓库并列即可）】
1) BDG 清洗能耗：bdg_cleaned_output\（与 building_energy_system 同级）
2) 规范 PDF 知识库：优先 building_energy_system\kb_documents\，否则工作区根下 kb_documents\ 或 知识库所需文档\
   将 PDF 放入上述任一目录后运行索引脚本（见下）。环境变量 KB_ROOT 可强制指定目录。
3) 司空合并语料 sikong_sft_all.jsonl：优先 …\BDG数据集\sft_merged\，其次 building_energy_system\sft_merged\
   若需从原始 JSON 重新合并：
     python <BDG数据集>\merge_sikong_sft.py
   原始 JSON 默认目录为 <BDG数据集>\司空大模型\（可用 SIKONG_SRC_DIR / SIKONG_OUT_DIR 覆盖）。
   后端读取路径可用环境变量 SIKONG_JSONL 覆盖。

【赛题能力对照（后端已实现）】
- 多条件能耗查询：GET /api/energy/records
- 三类统计：时段汇总 /stats/period、COP 演示 /stats/cop-proxy、异常分析 /stats/anomalies
- 可视化数据：/stats/timeseries（labels+values，供 ECharts）
- 报表导出：/stats/export/csv
- 领域知识：PDF 全文检索 /kb/search + 司空语料 /sikong/search
- 智慧运维（纯 RAG）：POST /assistant/rag-answer（PDF+司空检索并拼装回答，无 LLM）
- 检索原始片段：POST /assistant/knowledge-merge（PDF+司空，供自定义拼装）
- MCP 工具清单（映射用）：GET /api/mcp/tools
- 严格 MCP（stdio 进程）：在 backend 目录运行 python -m app.mcp_server（不要在该终端手动输入/回车）
- V2.0 强化：POST /v2/vision/upload（Query：mode、prompt、conf 可选；默认 YOLO-World；需 ultralytics + CLIP，见 backend\requirements-v2-vision.txt）、/v2/twin/scene、/v2/ops/suggestions、/v2/forecast/energy、/v2/reports/{operations|esg}

【命令】
1) 知识库索引（PDF 变更后）
   cd d:\BDG数据集\building_energy_system\backend
   python scripts\ingest_kb.py

2) 后端（默认 8765，避免 Windows 占 8000）
   cd d:\BDG数据集\building_energy_system\backend
   python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8765
   文档: http://127.0.0.1:8765/docs
   若 uvicorn 报 WinError 10013（端口被拒绝）：换端口再试，例如
     python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 18888
   浏览器打开 http://127.0.0.1:18888/api 应返回 JSON（含 examples），不是 {"detail":"Not Found"}。

3) 正式 Web 前端（Vue3 + Vite，推荐）
   cd <本仓库>\building_energy_system\frontend
   pnpm install
   pnpm dev
   浏览器一般为 http://127.0.0.1:5173 ，Vite 将 /api、/health、/docs 等代理到 8765（见 frontend\vite.config.js）
   或在 building_energy_system 根目录：npm install && npm run dev（同时起后端+前端，见 README.md）

4) 临时测试前端（旧版静态页 + Node 代理，可选）
   cd <本仓库>\building_energy_system\frontend_test
   npm start
   浏览器 http://127.0.0.1:3000 ，API 根地址留空（Node 默认代理到 8765）
   后端若改端口（如 18888），必须与代理一致，例如先执行：
     set BACKEND_URL=http://127.0.0.1:18888
   再 npm start

【若出现 {"detail":"Not Found"}】
- 多半是后端未在本机成功监听，或前端代理端口与后端不一致。
- 先单独打开后端文档页：与 uvicorn 端口一致，例如 http://127.0.0.1:18888/docs
- 再访问同端口的 http://127.0.0.1:18888/api ；能访问则说明 API 正常，再检查 BACKEND_URL。

环境变量：ENERGY_CSV、METADATA_CSV、DATA_DICTIONARY_CSV、KB_ROOT、KB_INDEX_DB、SIKONG_JSONL；
清洗脚本 BDG_DATA_DIR、BDG_OUT_DIR；合并脚本 SIKONG_SRC_DIR、SIKONG_OUT_DIR。
